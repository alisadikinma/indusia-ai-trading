## Design

### 1. Goal

Build a 24/7 autonomous AI trading agent for crypto (Binance spot+futures, Blofin perp) that:

- Continuously analyzes market state via Claude as the reasoning layer
- Executes auto buy/sell with hard risk guardrails
- Validated against multi-year historical backtest **and** several weeks of paper/forward testing before going live (per latest operator instruction — supersedes earlier "skip paper" choice)
- Goes live with $100–500 capital after backtest + paper-trade sign-off

### 2. Tooling decision: Claude Code CLI > OpenClaw — VALIDATED VIA NLM

NotebookLM deep research over 84 sources confirms the WebSearch verdict and surfaces additional security data not in the original sources:

| Dimension | Claude Code CLI | OpenClaw |
|---|---|---|
| Real-money $1k Polymarket benchmark (48h) | **+$13,216 (+1,322%)** via "sum-to-one" arbitrage on YES/NO contract dislocations, sub-800ms execution | **Total liquidation** ($1,000 → $0); infrastructure jitter prevented sustained <800ms latency |
| Cost economics | Managed API spend, fixed Max/Team subscription; mitigation: prompt caching with **5-min TTL trap** to manage | Variable token burn rate; local Ollama option exists but adds latency |
| Reliability | Managed CLI stability, low operator overhead | Self-hosted; per NLM: *"infrastructure maintenance bleeding into agent work"* |
| **Security disasters** | Sandboxed Cowork model, enterprise trust boundaries | **CVE-2026-25253 (RCE) affects 770,000 agents**; **~20% of skill registry malicious (800+ planted skills)**; **900+ exposed servers** with credential leakage. Non-viable for capital management. |
| Ecosystem | MCP, sub-agents, Routines, hooks, file memory | Markdown skills + "Task Brain" (vulnerable to "ClawHavoc" malicious updates) |
| Production patterns to fork | [degentic-tools/claude-code-trading-terminal](https://github.com/degentic-tools/claude-code-trading-terminal), [alsk1992/CloddsBot](https://github.com/alsk1992/CloddsBot), [stephengpope/thepopebot](https://github.com/stephengpope/thepopebot) | Skill marketplace (untrustworthy per registry data) |

**Verdict: Claude Code CLI for the brain. OpenClaw is rejected outright** — security profile alone disqualifies it for real capital management.

### 3. Architectural pivot: fork Freqtrade instead of building `trader-svc` from scratch

NLM research surfaced [**Freqtrade**](https://github.com/freqtrade/freqtrade) (25,000+ stars, since 2017, Python, 30+ exchanges via CCXT, native FreqAI ML plugin, mature backtest engine) and the [**PULSE Protocol**](https://dev.to/pulse_protocol_842706b157/i-connected-claude-ai-to-freqtrade-in-5-lines-of-codepublished-true-29ce) — an open semantic messaging standard for Claude→Freqtrade signal handoff in ~5 lines of code.

This eliminates 60–70% of the original build scope. Freqtrade already provides:

- Order execution + lifecycle management
- Risk manager (max open trades, stop-loss, trailing-stop, ROI tables)
- Multi-exchange via CCXT (Binance + Blofin both supported)
- Backtesting engine (Vectorized + event-based modes)
- Hyperparameter optimization (Hyperopt)
- FreqAI plugin for ML strategy training
- Web UI (FreqUI) for monitoring + manual override
- Telegram + Discord notifications + control commands

**We do NOT rewrite this.** We fork freqtrade and add the Claude oversight layer.

**Roles separated cleanly:**

- **Claude Code CLI = oversight brain.** Every 5–15 min: read recent OHLCV + signal queue, judge regime (trend/range/volatile), approve/veto Freqtrade signals, set position size multiplier, write append-only journal entry. Non-deterministic, slow, never on hot path.
- **Freqtrade = deterministic execution body.** Sub-100ms order placement, websocket fills, atomic risk checks. Battle-tested by 25k+ users. Receives PULSE signals from Claude, validates locally, places order via CCXT.
- **Postgres = single source of truth.** Both processes read/write here.
- **NautilusTrader = optional second backtest engine** when a strategy needs tick-level fidelity (Freqtrade native is bar-level; NautilusTrader bridges research-to-prod gap per [autotradelab 2026 review](https://autotradelab.com/blog/backtrader-vs-nautilusttrader-vs-vectorbt-vs-zipline-reloaded)).

### 8. ⚠️ Operator-decision corrections (from NLM + cumulative thinking)

#### Win rate framing — replaced

NLM directly flags "super tinggi win rate" as an amateur-bot-community framing. **Replace with: optimize for expectancy and Sharpe.** A 40% win rate with 4:1 R:R beats a 75% win rate with 1:2 R:R both in backtest and live. This is the most important framing change before strategy selection.

#### Skip-paper-trading — reversed

Earlier operator chose backtest-only → live. Latest operator instruction reverses this: paper trading several weeks. Plan reflects the reversal. Good move — backtest-only-to-live is the highest-risk decision class in algorithmic trading.

#### Capital cap — kept conservative

$100–500 live remains. NLM independently recommends "$50–$500 strict capital caps."

### 9. Risk rails (enforced in Freqtrade config — outside Claude's reach)

- Max position size: 25% of equity per trade (`stake_amount`)
- Max concurrent positions: 3 (`max_open_trades`)
- Daily loss circuit-breaker: –5% equity → halt 24h, Telegram alert (custom guard)
- Per-trade stop-loss: 2× ATR(14) trailing (`trailing_stop`)
- Max drawdown kill switch: –20% from peak → liquidate all, halt indefinitely (custom protection)
- API key rotation schedule: every 30 days (mitigates OpenClaw-class credential leakage)
- **Iron rule:** Claude can VETO trades but cannot OVERRIDE a risk-rail halt. Different process, different file ownership.

### 12. Open questions for `gaspol-plan` phase

1. **Strategy v1 specifics:** trend-follower (EMA20/50 + ADX>25 + ATR stops) vs Polymarket-style "sum-to-one" arb (more complex but proven in benchmark) vs funding-rate basis arb. Recommend trend-follower for v1 (highest understandability, lowest exec-latency requirement).
2. **Repo structure:** monorepo with `freqtrade-fork/` + `claude-routines/` + `pulse-bridge/` + `infra/` (Postgres + systemd units).
3. **TimescaleDB partitioning:** monthly chunks on `ohlcv`, retention 11 years.
4. **Routine cadence:** 5-min default; faster (1-min) if strategy is mean-reversion on lower timeframes.
5. **Telegram kill-switch authentication:** HMAC of `/halt` command + Telegram user-ID allowlist. Prevent unauthorized liquidation via stolen webhook.
6. **MEV / front-running response:** if backtest reveals a sub-second arb, what's the retry-and-give-up protocol when front-run? (NLM raised this — likely answer: skip, log, don't retry within same block.)
7. **Prompt caching strategy:** structure Claude's context so the static system+SOUL block stays under the 5-min TTL trap. Re-fetched OHLCV goes in a non-cached suffix block.

### Phase 9.5: Iteration Loop (CONDITIONAL — only fires if Phase 9 fails)

**Estimated time:** 5–10 days per cycle, max 3 cycles before architectural rethink
**Dependencies:** Phase 9 fail (any of 4 gate criteria not met across all 5 folds)
**Skip if:** Phase 9 PASSED on first run

> **The 3-loop learning model in this plan:**
> - **Loop 1 (operational, every trade):** Claude memory grows from post-mortems — auto, no code change
> - **Loop 2 (adaptive, every 24h):** FreqAI retrain on rolling window — auto, ML weights update
> - **Loop 3 (strategic, this phase):** Operator + Claude collaborative redesign when Phase 9 gate fails — semi-manual, with structured playbook below
>
> **Why Loop 3 is NOT auto:** RL-style auto-strategy-rewrite has known failure modes (reward hacking, distribution shift, audit-impossible). For live capital, strategy logic changes require human design + Claude analysis, not Claude writing trading code autonomously. Risk rails are immutable Iron Law.

**Files:**
- Create: `infra/scripts/diagnose_backtest_failure.py` — automated diagnostic suite
- Create: `infra/migrations/004_iteration_runs.sql` (table exists from Phase 1 bootstrap; this adds constraints + indexes)
- Create: `claude-routines/skills/backtest-diagnostics.md` — playbook skill for Claude to analyze failed backtest
- Create: `docs/decisions/iteration-NNN-<failure-mode>.md` (one per cycle, captured via `gaspol-adr`)
- Modify: `dashboard-ui/app/iteration-history/page.tsx` (Phase 1.5 builds the empty UI; this phase populates real data)

**Sub-phases:**

#### 9.5.A — Diagnose (1 day)

1. Write failing test: `diagnose_backtest_failure.py` produces structured JSON report given a `backtest_runs.id`. Expected error: `ImportError`.
2. Run, confirm fail.
3. Implement diagnostic suite — runs 4 queries against failed backtest:
   - **Overfit check:** train Sharpe vs test Sharpe gap per fold (>30% gap = overfit signal)
   - **Strategy-vs-ML check:** disable FreqAI gate, re-run pure rule-based — compare metrics
   - **Per-regime breakdown:** Sharpe / win-rate / expectancy per regime — find the bleeder
   - **Hyperopt stability:** top-10 param sets OOS variance — high variance = lucky params
4. Output: `diagnostic_report.json` with classified failure mode (`overfit | underfit | strategy_logic | regime_specific | hyperopt_unstable`).
5. Invoke Claude with `backtest-diagnostics.md` skill: read report, propose 1–3 specific hypotheses for fix.
6. Run diagnostic test, confirm pass against fixture.
7. Commit: `feat(iteration): diagnostic suite + claude analyst skill`.

#### 9.5.B — Hypothesis + ADR (0.5 day)

1. Operator reviews Claude's hypotheses from Step A5.
2. Capture chosen fix via `gaspol-adr`: failure mode, hypothesis, planned change, expected metric improvement.
3. Insert row to `iteration_runs` table: `cycle_n, failure_mode, hypothesis, adr_ref, started_at`.
4. Commit: `docs(iteration-N): ADR + hypothesis`.

#### 9.5.C — Implement fix (2–7 days, depends on chosen option)

Choose ONE based on diagnosis:

| Diagnosis | Fix option | Effort |
|---|---|---|
| Overfit | Reduce XGBoost depth (6→4), add L2 reg, longer training window (180→365d) | 2 days |
| Underfit | Add features (volume profile, order flow imbalance, funding trend), try ensemble | 3 days |
| Strategy weak in specific regime | Add regime filter (only trade in trending; veto in ranging) | 1 day |
| Hyperopt unstable | Switch to `SharpeHyperOptLossDaily`, reduce epochs to 1000, mandate top-10 OOS pass | 1 day + re-hyperopt time |
| Wrong timeframe | Switch from 15m to 1h primary, add 4h regime context | 3 days |
| Universe issue | Reduce to BTC-only; revisit ETH later if BTC profitable | 1 day |
| Wrong model class | Try LightGBM tuning, or CatBoost (similar API to XGBoost) | 3 days |
| Strategy fundamentally wrong | Replace strategy entirely (mean-rev → momentum, etc) | 7 days |

For each, follow Phase 3-7 TDD cycle (write test, fail, implement, pass, commit).

#### 9.5.D — Re-run Phase 9 walk-forward

1. Trigger: `bash infra/scripts/walk_forward.sh --strategy-version v1.N+1`.
2. Compute time: 4–6 days (same as original Phase 9).
3. Update `iteration_runs` row with `completed_at`, before/after metrics.

#### 9.5.E — Decision gate

```
IF all 4 gate criteria PASS in all 5 folds:
  → Update iteration_runs.outcome = 'PASS'
  → Forward to Phase 10 (paper trade)
  
ELIF cycle_n < 3:
  → Update iteration_runs.outcome = 'FAIL_RETRY'
  → Loop back to 9.5.A with new hypothesis (Claude must propose DIFFERENT fix from previous cycles)
  
ELSE (3 consecutive fails):
  → Update iteration_runs.outcome = 'FAIL_ESCALATE'
  → ARCHITECTURAL RETHINK GATE — full pause, operator review:
    - Is this asset class wrong? (e.g., crypto fundamentally not amenable to this strategy)
    - Is this timeframe wrong? (15m noise too high)
    - Should we change strategy CLASS (trend → mean-rev → arbitrage)?
    - Should we change scope (BTC-only? add altcoins later?)
  → Capture decision via gaspol-adr, possibly revert to Phase 3 with full strategy redesign
```

**Verification per cycle:**
- [ ] Diagnostic JSON report produced and committed under `docs/research/iterations/`
- [ ] ADR captured for hypothesis with measurable expected improvement
- [ ] All 4 gate criteria evaluated explicitly (no hand-waving)
- [ ] `iteration_runs` table has clean before/after metrics
- [ ] If FAIL_RETRY: next cycle's hypothesis must be MATERIALLY different (not param tweak)
- [ ] If FAIL_ESCALATE: operator-approved ADR for architectural change

**Gate:** Cannot exit phase without either PASS forward, or escalated ADR for rethink. **No silent advance.**
